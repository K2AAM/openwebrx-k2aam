# ALE integration 0.5.1 — mobile observer and idle scheduling

The C++ decoder remains 0.1.0; the 0.5 series adds a bounded SQLite reception log and read-only log/export requests. Version 0.5.1 corrects source occupancy while the last browser is absent and restores an opted-in tab to its existing scan after a reload into AM. It does not start scanning after reboot.

Current local checks:

- Native source occupancy and ServiceScheduler methods are executed from the repository AST with substituted hardware startup and timers. Tests reproduce last-browser removal, verify the active scan prevents idle profile takeover, and verify explicit profile changes, Stop and failure still release ownership. This establishes native scheduling logic, not an overnight physical iPhone test.

- 46 Python decoder/protocol/installer/helper/scanner/log tests passed. New cases exercise reopening a database, repeated/exact radio text, source-only station aggregation, receiver isolation, rejecting activity/test/bad records, retention, concurrent writers, paginated exports with a fixed end cursor, restore without retuning, continued live decoding on a disk error and recovery, scoped requests, and upgrade from 0.4.0 without deleting reception data.
- The 30 existing JavaScript scanner/catalog/native-tuning assertions and 16 observer/session assertions passed. Observer cases cover returning from AM, no duplicate Start/hardware retune, receiver/session isolation, Stop/manual intent clearing, stopping state, storage denial, stale status replies around Start/Stop and timer cleanup.
- 13 focused Chromium checks passed using the actual bundled RNNoise model through an AudioWorklet, plus the stations-heard UI, escaped addresses, real CSV download over two pages, formula neutralization, Clear behavior, phone overflow and log failures independent of scanner control. Desktop and phone screenshots were visually inspected. Browser RF and transport remain simulated.
- The full receiver browser suite, mobile WebKit startup, Python sanitizers and Studio DSP/model regressions are included in CI. See the branch's Receiver UI workflow for the published commit's results.

Persistence has been verified with real SQLite files in temporary directories. A controlled OWRX restart and overnight reception on the physical receivers remain operator checks. The development environment has no physical SDR or full native pycsdr stack. No receiver was accessed or restarted by this update.

The log retains the newest 50,000 server-scanner decoder events across receiver IDs. Counts are retained decoded events, not verified independent transmissions or resolved station identities. Source addresses alone populate Stations heard; destinations do not establish reception from that station. Manual/browser-only sessions and TEST AUDIO do not enter the durable log. The existing latest-250 display is restored from disk after restart without starting a scanner. SQLite failures are visible and do not stop live decoding. Uninstall keeps the database.

## Earlier receiver and scanner evidence

Receiver evidence supplied by the operator now includes an off-air ADW sounding at 11226 kHz, followed by reports of PLA and HAW addresses. These are decoded addresses, not independently verified station locations. The operator subsequently reports ADW and JNR decodes after the 0.3.0 server update; a supplied screenshot also contains OFF sounding events. That confirms operator-observed live decoding on the Airspy installation, while no-browser operation, restart behavior and SDRplay compatibility still need receiver checks. The operator has since reported the 0.4.0/0.3.1 installation working; the 0.5-series log/mobile updates are not yet receiver-tested. Earlier reference tests, injected panel messages and 16,000-byte/s PCM input checks alone did not establish RF decoding.

The supplied Signal Wiki sample decodes after MP3-to-8 kHz PCM conversion. A continuing-stream check recovers its text with trailing silence before EOF. That user-supplied audio is not redistributed. Two earlier off-air recordings produced no offline decoder events; their signal identity remains unconfirmed.

The development environment lacks a complete RF/pycsdr stack. Backend worker lifecycle and transport tests use simulated sources and chains; the native factory interface is checked with substituted modules. Actual SDR retuning, native resampling, no-browser reception, scanner hold performance and weak-signal behavior require the receiver trial. The provisional 250 ms settle interval is not a hardware acknowledgement. Dwell remains 3–60 seconds: 2–5-channel/second fast scanning is not implemented or measured.

Server scanning continues on tab hide/close until explicit Stop, source failure/shutdown, a profile/sample-rate/unexpected-center change, or a denied hardware retune. With 0.5.1, idle-service profile scheduling waits while a server scan reserves active use, then resumes when the worker releases it. Explicit profile changes still stop scanning. No scan automatically resumes after an OWRX restart. The prior release retained 250 messages in memory; 0.5.0 adds the persistent log described above. Decodes also go to the normal openwebrx journal with normal system retention. The optional browser scanner still stops when its tab is hidden.

No receiver was accessed or restarted during development. The installer checks and backs up native files, including connection.py, without changing profiles, RIG Dock runtime assets or plugin init. The exact known antenna connection hook is retained only when the remaining source matches the supported stock hash. Other customized connection.py variants are rejected. ALE uninstall restores the original antenna-patched file; uninstall ALE before removing that antenna installation. Deployment requires a service restart and browser reload. 3G ALE and transmit are not implemented.

Scan preferences are stored per SDR in browser localStorage, with no startup action. This is not server configuration persistence or reboot resume. The compact ALE display preserves decoded message text in raw details and keeps repeated events; it does not establish address identity or prove independent transmissions from repeated rows.
